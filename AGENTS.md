# AGENTS.md

Instructions for AI coding agents working in this repository.

## Project Snapshot
- Static site for Whitegate Observatory, deployed via GitHub Pages.
- Forecast content is generated by Python build scripts and copied into `dist/` during CI.
- Primary workflow is in `.github/workflows/astro.yml`.

## Read First
- Overview and deployment notes: [README.md](README.md)
- Current architecture and responsibilities: [ARCHITECTURE.md](ARCHITECTURE.md)
- Planned refactor direction: [REFACTORING_PLAN.md](REFACTORING_PLAN.md)

Link to these docs instead of duplicating them in changes or summaries.

## Verified Commands
- Install dependencies:
  - `pip install -r requirements.txt`
- Local generation (requires API keys in env):
  - `python astro_build.py --out dist/astro`
  - `python fish_build.py --out dist/fishing`

Notes:
- CI currently uses `astro_build.py` as the main generator in `.github/workflows/astro.yml`.
- If API keys are missing, generator runs may fail; document what you could not verify.

## Required Environment Variables
- `METEOSOURCE_API_KEY`
- `WORLD_TIDES_KEY`

In CI these are expected as GitHub Actions secrets.

## Repository Conventions
- Keep source pages in repository root (for example `index.html`, `astro-photography.html`) and shared assets under `assets/`.
- Treat `dist/` as generated deployment output from CI.
- Keep changes minimal and focused; avoid broad rewrites unless explicitly requested.
- Prefer updating existing structure and naming unless there is a clear requirement to change it.

## Deployment Workflow Expectations
- GitHub Pages deployment is triggered by pushes to `main` and by a schedule in `.github/workflows/astro.yml`.
- For deployment-intended changes, ensure work is commit-ready and push-ready.
- If asked to deploy, commit and push to `main` after verification.

## Known Pitfalls
- Iframe path differences may appear between local preview and deployed Pages paths for astro outputs.
- Browser caching can hide newly generated forecast content after deployment.
- This repository includes architecture notes that may lag behind current workflow behavior; verify against `.github/workflows/astro.yml` before major edits.

## Preferred Change Pattern
1. Read relevant docs first.
2. Make the smallest viable change.
3. Run the narrowest validation available.
4. Summarize what changed, what was validated, and any blockers (especially missing API secrets).
